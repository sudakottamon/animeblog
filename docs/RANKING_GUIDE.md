# ランキングデータ作成ガイド

`src/content/rankings/<slug>.yaml` を作る・直すときのルール。スキーマは `src/content.config.ts` の `rankings`。
作ったら `node scripts/check-rankings.mjs <slug>` で点検する（ビルドは担当者がまとめて行う）。

## サイトの仕組み（データが何に使われるか）

- 「勢（bases）」ごとにタブが分かれる。タブごとに候補キャラ・運営の判定・ユーザーのティア表投稿が別。
- **前の勢のタブには、後ろの勢でしか描かれていない情報（キャラ、能力、形態、戦闘結果）を一切出さない。** ネタバレ漏れはこのサイトで最悪の不具合。
- ユーザーは候補キャラを全員 S〜D に並べないと投稿できない。候補が多すぎると投稿が面倒になるので 12〜22人に収める。
- 運営の点数（editor.score, 1〜100）はティアに変換される: 90以上=S、80台=A、70台=B、60台=C、59以下=D。同じ段の中は点数の高い順に左から並ぶ。
- 運営の判定は「判定理由（note）」と「根拠（evidence）」をページにそのまま表示する。

## 判定の基準

- 根拠は**作中で描かれた場面**。ファンブックや作者発言は補助。描写と食い違えば描写を優先。
- 比べ方は「初見・1対1・相性込みの総合力」。スポーツ作品は「選手としての実力」、戦記・群像作品は作品に合わせて（例: キングダムは武力と指揮）、基準を note で明示する。
- 回想だけの人物も候補に入れてよいが、note にその旨を書く。

## 各フィールド

下は形式の見本。中身（話数・巻数など）は実データを作るときに必ず確認し直すこと。

```yaml
work: 呪術廻戦                 # 作品名（正式表記）
title: 呪術廻戦 最強キャラランキング
description: 呪術廻戦の最強キャラをアニメ勢・漫画・原作勢に分けてティア表で決めます。候補キャラを全員並べて投稿すると、みんなのティア表に反映されます。
published: 2026-10-23
updated: 2026-10-23
bases:                          # 情報量が少ない順
  - id: anime
    label: アニメ勢
    range: TVアニメ第2期（渋谷事変）＋劇場版0まで
  - id: manga
    label: 漫画・原作勢
    range: 原作完結（単行本全30巻）まで
services: [cmoa, ebookjapan, dmmbooks]
related: []
candidates:
  - id: gojo
    name: 五条悟
    affiliation: 呪術高専 教師
    cv: 中村悠一
    editor:
      anime:
        score: 98
        note: 渋谷で特級呪霊をまとめて処理した。設定の「最強」に描写が追いついている。
        evidence:
          - "第1期 第7話: 漏瑚を無量空処で一方的に制圧した"
          - "第2期 第9話: 渋谷で改造人間と呪霊の群れを一人で処理した"
      manga:
        score: 95
        note: 宿儺戦は敗北。ただし魔虚羅の適応を挟んだ上での決着で、地力の評価は落ちない。
        evidence:
          - "単行本26巻: 宿儺と領域の押し合いで互角以上に渡り合った"
  - id: kashimo
    name: 鹿紫雲一
    affiliation: 死滅回游の参加者
    appears: manga              # アニメ勢のタブには出ない
    editor:
      manga:
        score: 89
        note: 宿儺に一撃を通した数少ない術師。
        evidence:
          - "単行本27巻: 宿儺戦で幻獣琥珀を解放した"
```

### bases（勢）

- 漫画原作でアニメが途中まで → `anime`（アニメ勢）＋`manga`（漫画・原作勢）
- アニメが原作の最後まで描き切っている → `anime` 1つだけ（label: アニメ・漫画勢、range: 「アニメ・原作とも完結まで」など）。このときは appears を書かず、editor も anime だけ。
- 小説原作 → `anime` / `manga`（コミカライズ。label: 漫画勢）/ `novel`（label: 原作（小説）勢）。コミカライズがアニメより手前までしか進んでいなければ manga を省いて anime と novel の2つにする。
- 原作がWeb漫画など別にある（ワンパンマンのONE版など）→ `original`。
- アニメ化されていない作品は `manga`（または `novel`）1つだけにしてよい。
- 並びは必ず**情報量の少ない順**。逆にするとネタバレになる。
- range は2026年10月時点の状況を WebSearch で確認して具体的に書く（「TVアニメ第3期（〇〇編）まで」「原作完結（全〇巻）まで」「単行本最新〇巻まで」）。確認できなければ「TVアニメの放送済み範囲まで（2026年10月時点）」と控えめに。

### candidates（候補）

- 12〜22人。その作品の最強議論で名前が挙がるキャラを中心に、主人公側と敵側をバランスよく。形態違いは同じキャラにまとめる。
- id: 半角英小文字・数字・ハイフン（ローマ字）。作品内で重複不可。
- name: 作中の表記。affiliation: 所属・肩書きを短く。
- cv: アニメの声優。**WebSearch で確認できて確信がある場合だけ**。交代があった・不安があるなら省く。
- appears: そのキャラ（またはそのキャラの強さが分かる描写）が初めて出る勢。既定は anime。アニメ未登場・アニメでほぼ戦っていないキャラは後ろの勢。**迷ったら後ろの勢**。

### editor（運営の判定）

キャラが登場する勢すべてに `score` / `note` / `evidence` を書く（appears より前の勢には書かない）。

- **note**（判定理由）: 1〜2文。その勢の範囲で描かれた出来事だけを根拠に、事実で言い切る。後の展開を匂わせる書き方も禁止。
- **evidence**（根拠）: 1〜3件。1件1文で「どこで: 何が起きたか」。
  - どこで = 「第2期 第9話」「単行本26巻」「第120話」「劇場版『〇〇』」「〇〇編」など。話数や巻数が確認できなければ編・章の名前でよい。**確認できない数字は書かない**。
  - 何が起きたか = 勝敗・使った技・相手。その勢の範囲の場面だけ。
  - 前の勢から評価が変わらない場合、後ろの勢の evidence は省略してよい（ページでは前の勢の根拠を引き継いで表示する）。そのとき note は「原作でも評価は変わらない。」程度でよい。
- 点数は作品の強さ議論の一般的な認識に沿いつつ、S〜D に幅を持たせる（全員 S や全員 A にしない。下位は C〜D も使う）。勢が進んで描写が増えたら見直す。
- 文体: 見本のように淡々と事実で書く。「〜と言えるでしょう」「圧倒的な」「まさに」「間違いなく」「！」は使わない。

### その他

- published / updated: 作成日（新規）または更新日。
- services: `[cmoa, ebookjapan, dmmbooks]`。related: `[]`。
- **evidence の各要素は必ず `"…"` で囲む**（「第9話: …」を引用符なしで書くと YAML がキーと値のペアとして読む）。note など他の文字列も `: `（コロン＋空白）や `#` を含むなら引用符で囲む。

## 品質

- 事実（勝敗、アニメがどこまで放送済みか、声優、話数・巻数）は WebSearch / WebFetch で確認する。記憶だけで書かない。
- 自信のない記述は書かない。キャラ数より正確さを優先。
- 作ったら `node scripts/check-rankings.mjs <slug>` を実行し、指摘がゼロになるまで直す。
